# 系统说明

## 1. 系统组成

系统从摄像头或视频文件读取图像，完成目标检测后，再结合连续帧、区域配置和外部业务信息生成事件。告警先写入本地数据库，再由后台线程发送到告警服务，不会因为网络超时阻塞视频推理。

默认配置包含人员进入管控和低压微型断路器状态模型。

## 2. 人员进入管控

人员检测模型输出人员位置，ByteTrack 为同一人员分配连续的 `track_id`。系统取检测框下部点作为人员落点，判断该点与电子围栏多边形的关系。

进入围栏后，系统按以下顺序检查：

1. 该区域是否允许人员进入；
2. 当前身份是否在区域授权名单内；
3. 当前时间是否在授权时段内。

对应的处理结果如下：

| 情况 | 处理 |
| --- | --- |
| 身份和时段均合法 | 放行，不报警 |
| 身份无权限 | 产生进入告警 |
| 超出授权时段 | 产生超时进入告警 |
| 暂时无法确认身份 | 产生待复核事件 |

身份信息通过 `runtime/access_identity_context.json` 与跟踪 ID 关联。文件超过配置的有效时间后，对应人员按未知身份处理。

可见光摄像头使用 `power_visible` 模型，旧 CCTV 或热成像摄像头使用 `legacy_mixed` 模型，系统按摄像头类型选择对应模型。

## 3. 断路器状态监测

系统在每帧画面中实时识别 MCB、RCD 和总隔离开关，并对 MCB 建立短时跟踪。只有检测到 MCB 后才读取其拨杆位置；RCD 和总隔离开关不会进入 MCB 状态机。设备离开画面时不保留检测标签，拨杆受遮挡或几何特征不足时输出 `UNKNOWN`。

`TRIP` 和 `MICRO_TRIP` 是时序事件，不是单帧图像类别。当前配置按视频时间判定：

- CLOSED 高置信连续稳定 30 秒后进入布防；
- OPEN 或外观偏离持续 0.5 至 1.2 秒，随后稳定恢复 1 秒，记为 `MICRO_TRIP`；
- OPEN 或外观偏离持续达到 3 秒，记为 `TRIP`；
- 恢复 CLOSE 后，发送与原事件相同 `event_id` 的 `RECOVERED`。

低置信设备框和 `UNKNOWN` 状态不会进入状态机。CLOSED 还需在同一跟踪对象上连续保持0.5秒，用于排除手部遮挡造成的短促误判。视频时间间隔超过0.5秒时，未确认的状态也会清零。事件结束后需要重新建立稳定闭合基线。

计划分闸、检修模式等信息可以抑制告警。系统也可以结合保护动作、跳闸线圈或辅助触点信号对事件进行多源确认。

## 4. 告警处理

每个事件包含 `START` 和可选的 `RECOVERED` 阶段。事件先写入 JSONL 日志和 SQLite outbox，再投递到 HTTP 接口。

投递 ID 由事件 ID 和阶段生成，同一阶段重试时不会在服务端重复入库。发送失败后按指数退避重试，程序重启后会继续处理未完成记录。
