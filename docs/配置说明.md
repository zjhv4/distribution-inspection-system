# 配置说明

## 人员检测模型

普通可见光配电、变电摄像头使用 `power_visible`，旧 CCTV 或热成像摄像头使用 `legacy_mixed`，按画面类型选择对应模型。

## 电子围栏

`polygon` 使用图像像素坐标，按顺时针或逆时针填写多边形顶点：

```yaml
zones:
  - name: restricted_area
    polygon: [[180, 120], [1650, 140], [1700, 960], [150, 940]]
```

建议在原始分辨率下取点。摄像头角度、裁剪或输入分辨率发生变化后，需要重新标定。

## 身份和授权时段

```yaml
access_policy: scheduled_authorized
unknown_identity_action: review
allowed_identity_ids: [staff_001, staff_002]
access_windows:
  - days: [0, 1, 2, 3, 4]
    start: "08:00"
    end: "18:00"
```

`days` 中 0 表示星期一，6 表示星期日。跨夜时段可以写成 `22:00`–`06:00`。

身份服务需要向系统提供身份编号、授权状态和允许进入的区域。身份信息过期或无法匹配时，相关事件进入待复核流程。

## 断路器区域

断路器默认使用现场参考图判定拨杆位置，不使用通用整图分类权重作为主判据。

每台断路器应使用独立的资产名称和固定区域：

```yaml
rois:
  - name: QF1
    bbox: [820, 260, 1110, 760]
    closed_reference: runtime/breaker_references/QF1_closed.jpg
    open_reference: runtime/breaker_references/QF1_open.jpg
```

`bbox` 顺序为 `[x1, y1, x2, y2]`。两张基准图必须来自同一摄像头、同一 ROI 和同一台设备。可使用 `scripts/capture_breaker_references.py` 从现场视频或摄像头采集。画面遮挡或相似度不足时输出 `UNKNOWN`。

## 事件时间

时序事件默认按视频时间判定，与视频帧率和抽帧频率无关：

```yaml
temporal_seconds_enabled: true
observation_confidence: 0.98
arm_closed_seconds: 30.0
micro_trip_min_seconds: 0.5
micro_trip_max_seconds: 1.2
trip_confirm_seconds: 3.0
recovery_seconds: 1.0
max_observation_gap_seconds: 0.5
rearm_after_event: true
```

`observation_confidence` 控制进入状态机的最低状态置信度。`arm_closed_seconds` 表示设备需要先稳定闭合多久才开始监测事件。时间戳间隔超过 `max_observation_gap_seconds` 时，未确认序列自动清零。

## 告警接口

| 接口 | 用途 |
| --- | --- |
| `POST /alerts` | 接收告警 |
| `GET /health` | 健康检查 |
| `GET /api/alerts?limit=100` | 查询最近告警 |
| `GET /acks/{delivery_id}` | 查询投递确认 |
| `GET /alerts` | 查看简单告警页面 |

## 上线前检查

1. 围栏边界与现场画面一致；
2. 身份信息能够正常更新；
3. 每个断路器区域只包含一台设备；
4. 手动模拟一次进入和恢复，确认后台收到 `START/RECOVERED`；
5. 用现场正常闭合画面完成布防检查；
6. 检查保护或辅助触点信号的接入状态。

## 常见问题

### 所有人员都显示待复核

检查身份信息是否过期，以及身份记录中的跟踪编号是否与当前检测结果一致。

### 人员在围栏外仍触发事件

检查围栏坐标是否按原始输入分辨率填写，并确认摄像头画面没有二次裁剪。

### 跳闸告警过快或过慢

调整 `micro_trip_*_seconds`、`trip_confirm_seconds` 和 `recovery_seconds`，无需按帧率换算。

### 告警未上传

检查告警服务的健康状态和待投递记录，并确认目标接口能够正常访问。
